# Миграция героев на объектный контракт

Миграция завершена 5 ноября 2026 года. Обязательный контракт находится в
[HOW_CREATE_HEROES.md](../.codex/HOW_CREATE_HEROES.md); здесь описаны итоговый
игровой путь, совместимость и выполненные проверки.

## Локальные стратегии

Все зарегистрированные идентичности реализованы отдельными `final`-классами
на базе `AbstractHero`:

| Пакет | Стратегии |
| --- | --- |
| `pudge` | `PudgeHero` |
| `lumeshard`, `bolotnik`, `bountycrow`, `faun` | `LumeshardHero`, `BolotnikHero`, `BountyCrowHero`, `FaunHero` |
| `zeus`, `moleminer`, `clownganger`, `izba` | `ZeusHero`, `MoleminerHero`, `ClowngangerHero`, `IzbaHero` |
| `ginseng`, `chronomlin`, `kikimora`, `ares` | `GinsengHero`, `ChronomlinHero`, `KikimoraHero`, `AresHero` |
| `plain`, `clownganger`, `izba` | `NoneHero`, `IllusionHero`, `BabaYagaHero` без активных способностей |

`HeroDefinition` создаёт стратегию с неизменяемыми локальными параметрами.
`HeroRules` остаётся типизированным контейнером; `HeroStatePolicy` отдельно
инициализирует и проверяет собственное состояние. Допустимая начальная фигура
и формы после превращения проверяются разными контрактами.

## Применение способности

`Game` создаёт реестр партии и передаёт его в подготовленные контексты.
`ActionEngine` получает поведение через `registry.get(actor.hero())` либо
`registry.ownerOf(ability)` для копии. Общая база проверяет готовность и схему
целей, затем вызывает единственный protected `previewAvailable(..., request)`.

Геометрия и предложенные эффекты находятся в локальном Hero. `HeroEffect`
содержит отдельную стоимость и типизированные операции; `AbstractHero` учитывает
стоимость один раз до применения операций и наград. Заимствованная способность
получает настоящего исполнителя и сохраняет его собственные ресурсы. Ginseng
не содержит диспетчеризации скопированных способностей.

Модули механик применяют операции в существующей последовательности, сохраняют
случайность и длительные состояния. Заряд за взятия начисляется через стратегию
настоящего исполнителя из реестра рабочей сессии. Пассивная месть находится
в `AresHero.onCaptured`; очередь дальнейших гибелей остаётся общей.
`SwallowMechanic` обслуживает проглоченного союзника по состоянию и ID владельца,
в том числе после расходования копии. События и прежние тексты журнала сохранены.

Занятость в каноническом предпросмотре определяется через `context.pieces`.
`Field` используется как фабрика шахматных фигур и исходная геометрия.
Проверки конца действия и загрузки используют политики реестра; непроверенный
результат не публикуется. Подсветка обеих стадий строится из полных запросов
и проходит тот же предпросмотр, что реальная команда.

## Единый API способностей

После миграции поддержка старого API прекращена по решению пользователя.
Удалены `LegacyPreview`, `HeroAbilities`, `LegacyHeroes`, `BorrowedEffects`,
все локальные `*Abilities` и методы героев, обслуживавшие только эти фасады.
В `Hero` и `AbstractHero` остался единственный вход предпросмотра:

```java
Hero hero = registry.get(actor.hero());
HeroEffect effect = hero.preview(context, request);
```

Для копии используется `registry.ownerOf(request.ability())` и тот же метод
с `request.borrowed() == true`. Исполнитель и цель находятся в `context.pieces`;
передавать их вторым независимым набором аргументов нельзя. Перегрузки `preview`
с отдельными фигурами, `previewRequest` и специальный
`Game.getDisplacementDestinations` удалены. Для подсветки второй клетки используется
общий `Game.getAbilityDestinations`.

Проверка готовности, список способностей и награда за взятие доступны у стратегии:
`availability`, `abilities`, `afterCapture`. Реакции обслуживают `CaptureReactions`
и модули. Чистые геометрические функции, нужные валидаторам и журналу, находятся
в локальных `*Hero`.

Адаптеры `game.mechanics.compat`, `HeroTypeCodec`, `GameEventXml` и каталоги
драфта 1–10 сохраняют схемы данных прежних сохранений. Формат сохранений и
существующие XML-файлы при удалении API не изменены.

## Ветки и проверка

Работа выполнялась в `codex/migrate-heroes-terrain`,
`codex/migrate-heroes-mechanics` и `codex/migrate-heroes-transforms` из одной
исходной точки. Итог объединён в `codex/migrate-all-heroes` и исходном рабочем
дереве. Ветка `dev` и её индекс не изменялись. Состав коммитов и история
подготовки: [BEFORE_MIGRATE_ALL_HEROES.md](../.codex/BEFORE_MIGRATE_ALL_HEROES.md).

Полный `bash gradlew :composeApp:jvmTest`: **714 тестов**, без падений, ошибок
и пропусков. Сохранены игровые проверки собственных и скопированных эффектов, чистоты,
стоимости и актуальной занятости. Удалены пять тестов исключительно упразднённого
API; остальные вызовы переведены на полный контекст и запрос.

Дифференциальные сравнения с исходной версией совпали:

| Проверка | Записей |
| --- | ---: |
| Собственные способности: готовность, статусы, цели и полное подготовленное состояние | 58 060 |
| Копии: все способности, три формы Ginseng, свободный/занятый слот союзника | 45 570 |
| Реальные команды, XML, загрузка и доступные ходы всех героев | 1 842 |
| Прежние сценарии команд и сохранений Пуджа/Ginseng | 2 811 |

Все 116 существующих изображений UI совпали попиксельно.
Исторические сравнения старого API зафиксированы в плане миграции; после его
удаления они не относятся к действующему контракту.
