# Графика Moba Chess

Сюда складываем подготовленные PNG для нового игрового интерфейса.
Папка независима от движка. Сейчас проект использует Compose Desktop;
LibGDX и автоматическая упаковка/загрузка этой папки ещё не подключены.
Добавление PNG сюда само по себе не меняет изображение в работающей игре.
Существующие ресурсы `composeApp/src/jvmMain/composeResources/drawable`
остаются на своём месте.

## Куда класть файлы

```text
art/
  heroes/
    pudge/
      sprite.png          # герой на доске
      portrait.png        # портрет для драфта и карточки
    zeus/
      sprite.png
      portrait.png
    ...                   # папки для всех HeroType, кроме NONE
  boards/
    default/
      board.png           # только квадратное игровое поле 8 x 8
      frame.png           # отдельная рамка с прозрачным отверстием
      tile_light.png      # необязательно: светлая клетка
      tile_dark.png       # необязательно: тёмная клетка
  environments/
    default/
      backgrounds/
        background.png    # фон под доской
      props/
        tree_01.png       # отдельные предметы вокруг доски
      foregrounds/
        foliage_01.png    # декор перед другими слоями
  shared/
    effects/              # общие эффекты и маркеры
    ui/                   # кнопки, панели, иконки
  source/                 # PSD, KRA, SVG и другие редактируемые оригиналы
```

Имена файлов выше — соглашение для подготовки графики, а не готовый API загрузчика.
Пустые папки сохранены в Git через `.gitkeep`; эти файлы можно оставить рядом с PNG.

## Герои

- Каждому герою соответствует папка по `HeroType` в нижнем регистре:
  `PUDGE` → `pudge`, `SUN_WUKONG` → `sun_wukong`, `BABA_YAGA` → `baba_yaga`.
  Это имена папок графики; существующие Java-пакеты переименовывать не нужно.
- Для начала достаточно `sprite.png` и, при наличии, `portrait.png`.
- Рекомендуемый стартовый размер спрайта: **512 x 512 px**, PNG RGBA,
  прозрачный фон. Это размер холста, а не обязательная высота самого персонажа.
- У всех спрайтов одинаковые масштаб, ракурс и точка опоры: центр основания
  персонажа в точке **(256, 448)**, если считать от левого верхнего угла холста.
  Оставлять примерно 32 px до краёв; оружие и эффекты не обрезать.
  Эти значения — начальное соглашение, которое проверим на первом герое в игре.
- Портрет: **1024 x 1024 px**, лицо и важные детали ближе к центру,
  чтобы картинка допускала обрезку в карточке. Фон может быть прозрачным или цельным.
- Если рисуются разные варианты команд, вместо `sprite.png` использовать
  `sprite_white.png` и `sprite_black.png`. До решения по дизайну достаточно одного.
- Иконки способностей при необходимости добавлять в `abilities/` внутри папки героя,
  эффекты — в `effects/`. Имена иконок согласовывать со стабильными ID способностей
  из enum героя, а не с переводом названия.
- Для покадровой анимации добавлять, например, `animations/idle/000.png`, `001.png`.
  Все кадры имеют одинаковый холст и точку опоры. Для обычного плавного перемещения
  по доске достаточно одного спрайта.
- Герой может иметь разные шахматные тела. Если для них потребуется разная графика,
  добавлять `bodies/rook.png`, `bodies/bishop.png` и т. п.; пока достаточно общего
  спрайта, а шахматное тело и команду интерфейс должен обозначать отдельно.
- `illusion`, `supernova`, `baba_yaga` имеют свои папки как отдельные идентичности.
  Обычные фигуры без героя при необходимости размещать в `shared/pieces/`.

## Доска

- Начальный ориентир для `board.png`: **2048 x 2048 px**, вид строго сверху,
  сетка 8 x 8 с клетками по 256 px. Край изображения совпадает с краем игрового поля.
- В `board.png` не включать рамку, окружение, фигуры, координаты, надписи и подсветки.
  Так координаты клеток останутся однозначными, а надписи можно будет переворачивать.
- Альтернатива цельной доске — две текстуры клеток `tile_light.png` и
  `tile_dark.png`, каждая **256 x 256 px**. Оба варианта одновременно не обязательны.
- Рамка `frame.png` — отдельный прозрачный слой. Размер её холста и прямоугольник
  отверстия нужно согласовать с макетом перед подключением; сам файл этого не задаёт.
- Для другой темы создать соседнюю папку, например `boards/forest/`.
- Наклонную доску пока не экспортировать как окончательный игровой ресурс:
  перспектива потребует другого расчёта координат и размещения фигур.

## Окружение

- Фон: стартовый ориентир **2560 x 1440 px**, если выбираем горизонтальный экран.
  Это предварительный размер; целевые платформы и ориентация ещё не зафиксированы.
- Фон должен допускать обрезку по краям под разные пропорции экрана.
  Не рисовать в него игровую доску, интерфейс и текст.
- Деревья, камни, свечи и другие предметы сохранять отдельными PNG RGBA
  в `props/`; элементы переднего плана — в `foregrounds/`.
- Не оставлять большие случайные прозрачные поля у предметов окружения.
  Фиксированный холст и точка опоры нужны прежде всего героям и кадрам анимации.
- Для другой темы создать `environments/forest/` с теми же подпапками.

## Общие требования и дальнейшее подключение

- Имена: латиница, нижний регистр, слова через `_`, без пробелов.
- PNG в цветовом пространстве sRGB; прозрачность настоящая, без нарисованной шахматки
  и без белого ореола на краях. Текст и цифры интерфейса рисуются кодом.
- Для мягкой рисованной графики готовим изображения с запасом разрешения;
  для пиксель-арта отдельно согласуем размер пикселя и масштабирование.
- Не собирать все картинки вручную в один лист и не увеличивать маленькие исходники
  до рекомендуемых размеров ради формального соответствия.
- Редактируемые оригиналы хранить в `source/`, сохраняя соответствующую структуру:
  например `source/heroes/pudge/character.kra`. Готовые PNG — в папках выше.
- При подключении LibGDX настроим экспорт PNG из `art/` в ресурсы клиента,
  упаковку в атласы и загрузчик. Атласы будут производными файлами;
  исходные PNG сохранятся отдельно. Крупные фоны необязательно включать в атлас.
